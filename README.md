# Blog API

A simple blog REST API built with **Express 5**, **Prisma ORM 8**, **TypeScript** and **PostgreSQL**.

## Tech stack

| Tool | Version | Purpose |
|---|---|---|
| Node.js | 24+ | Runtime |
| Express | 5 | HTTP server and routing |
| Prisma ORM | 8 (release candidate) | Database schema, migrations and typed queries |
| PostgreSQL | 15+ | Database |
| TypeScript + tsx | 7 / 4 | Language, and running `.ts` files directly |
| Swagger UI | 5 | Interactive API docs |

## Project structure

```text
.
├── openapi.yaml               # API spec (served as Swagger UI)
├── prisma.config.ts           # Prisma CLI config (contract path + DATABASE_URL)
├── migrations/                # Prisma migrations and refs (generated)
└── src/
    ├── index.ts               # Starts the server, graceful shutdown
    ├── app.ts                 # Express app, routes, Swagger, error handling
    ├── prisma/
    │   ├── contract.prisma    # Database schema (edit this)
    │   ├── contract.json      # Generated by `npm run contract:emit`
    │   ├── contract.d.ts      # Generated types
    │   └── db.ts              # Database client
    ├── routes/                # users, categories, tags, posts, comments
    ├── middleware/
    │   └── error-handler.ts   # 404 + error responses (maps Postgres errors to 400/409)
    └── utils/
        └── http-error.ts      # HttpError, parseId, requireFields
```

## Database schema

8 tables:

| Table | Description |
|---|---|
| `User` | Blog users, with a `USER` / `ADMIN` role |
| `Profile` | One-to-one with `User` (bio, avatar) |
| `Category` | One category per post (optional) |
| `Post` | Blog posts, with `DRAFT` / `PUBLISHED` / `ARCHIVED` status |
| `Tag` | Tags |
| `PostTag` | Many-to-many join between `Post` and `Tag` |
| `Comment` | Comments on posts |
| `Like` | One like per user per post |

Deleting a user deletes their profile, posts, comments and likes. Deleting a category keeps its posts and sets their `categoryId` to `null`.

## Getting started

### 1. Install dependencies

```bash
npm install
```

### 2. Start PostgreSQL

Use any PostgreSQL 15+ server. For a quick local one with Docker:

```bash
docker run -d --name blog-postgres \
  -e POSTGRES_USER=user -e POSTGRES_PASSWORD=password -e POSTGRES_DB=mydb \
  -p 5432:5432 postgres:17-alpine
```

### 3. Configure environment variables

```bash
cp .env.example .env
```

Then edit `.env`:

```env
DATABASE_URL="postgresql://user:password@localhost:5432/mydb"
PORT=3000   # optional, defaults to 3000
```

### 4. Create the tables

```bash
npm run contract:emit
npm run db:init
```

### 5. Run the server

```bash
npm run dev     # auto-restarts on file changes
# or
npm start
```

- API: http://localhost:3000/api
- Swagger docs: http://localhost:3000/api-docs
- Health check: http://localhost:3000/health

## API endpoints

Full request and response details are in Swagger at `/api-docs` and in `openapi.yaml`.

| Method | Path | Description |
|---|---|---|
| GET | `/api/users` | List users |
| POST | `/api/users` | Create a user |
| GET | `/api/users/:id` | Get a user with profile and posts |
| PATCH | `/api/users/:id` | Update a user |
| DELETE | `/api/users/:id` | Delete a user |
| PUT | `/api/users/:id/profile` | Create or update a profile |
| GET | `/api/categories` | List categories |
| POST | `/api/categories` | Create a category |
| GET | `/api/categories/:id` | Get a category with its posts |
| PATCH | `/api/categories/:id` | Rename a category |
| DELETE | `/api/categories/:id` | Delete a category |
| GET | `/api/tags` | List tags |
| POST | `/api/tags` | Create a tag |
| DELETE | `/api/tags/:id` | Delete a tag |
| GET | `/api/posts?page=1&limit=10` | List posts (paginated, newest first) |
| POST | `/api/posts` | Create a post |
| GET | `/api/posts/:id` | Get a post with author, category, tags, comments, likes |
| PATCH | `/api/posts/:id` | Update a post |
| DELETE | `/api/posts/:id` | Delete a post |
| POST | `/api/posts/:id/tags/:tagId` | Attach a tag |
| DELETE | `/api/posts/:id/tags/:tagId` | Remove a tag |
| POST | `/api/posts/:id/comments` | Add a comment |
| POST | `/api/posts/:id/likes` | Like a post |
| DELETE | `/api/posts/:id/likes/:userId` | Remove a like |
| PATCH | `/api/comments/:id` | Edit a comment |
| DELETE | `/api/comments/:id` | Delete a comment |

Errors always come back as `{ "error": "message" }`:

| Status | When |
|---|---|
| 400 | Invalid id, missing fields, or a referenced record doesn't exist |
| 404 | Record or route not found |
| 409 | Duplicate value (e.g. email, category name, tag already attached) |
| 500 | Unexpected error |

Example:

```bash
curl -X POST http://localhost:3000/api/users \
  -H 'Content-Type: application/json' \
  -d '{"email":"ali@test.com","name":"Ali"}'
```

## npm scripts

Pass extra flags after `--`, for example `npm run migration:plan -- --name add_slug`.

### App

| Script | Description |
|---|---|
| `dev` | Start the server in watch mode |
| `start` | Start the server |
| `typecheck` | Type-check the project with `tsc` |

### Contract (schema)

| Script | Description |
|---|---|
| `contract:emit` | Regenerate `contract.json` and `contract.d.ts` from `contract.prisma` |
| `contract:format` | Format `contract.prisma` |
| `contract:print` | Print the schema the config loads |
| `contract:infer` | Build a schema from an existing database |

### Database

| Script | Description |
|---|---|
| `db:init` | Create all tables in an empty database |
| `db:sync` | Emit the contract, then update the tables (quick local workflow) |
| `db:update` | Update tables to match the contract |
| `db:update:dry` | Preview `db:update` without applying it |
| `db:migrate` | Apply planned migrations |
| `db:migrate:show` | Preview which migrations would run |
| `db:verify` | Check that the database matches the contract |
| `db:sign` | Mark the database as matching the contract |
| `db:schema` | Show the live database schema |

### Migrations

| Script | Description |
|---|---|
| `migration:plan` | Emit the contract, then create a new migration |
| `migration:new` | Create an empty migration to write by hand |
| `migration:status` | Show pending migrations |
| `migration:list` | List migrations on disk |
| `migration:log` | Show migrations that have run |
| `migration:graph` | Show the migration graph |
| `migration:check` | Check migration files for problems |
| `migration:show` | Show one migration's contents |
| `migration:ref:list` | List refs |
| `migration:ref:set` | Point a ref at a schema version |

## Changing the schema

1. Edit `src/prisma/contract.prisma`.
2. Apply the change:
   - **Experimenting locally:** `npm run db:sync`
   - **Change to keep and share:**
     ```bash
     npm run migration:plan -- --name describe_change
     npm run db:migrate
     npm run db:verify
     ```
3. Run `npm run typecheck` to find code that needs updating.

## Notes

- **Prisma 8 is a release candidate.** The Prisma package versions are pinned exactly (`@prisma/orm-postgres@8.0.0-rc.13`, `prisma@8.0.0-rc.19`), because newer RC releases didn't work together. Don't upgrade them on their own.
- **Temporal polyfill.** Prisma 8 timestamp columns use the JavaScript `Temporal` API, which Node.js doesn't include yet. `src/prisma/db.ts` loads `temporal-polyfill` to add it.
- **Swagger docs are written by hand.** Update `openapi.yaml` when you change a route.
